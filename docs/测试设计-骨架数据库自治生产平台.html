测试摘要

测试的目标不是证明 Agent 永远正确，而是证明错误不会无证进入权威库，能够被发现、定位、回滚和重新执行。

发布级质量命题：任意正式发布物都必须能回答“由哪个 Job、哪些冻结输入、哪个执行器、哪个模型和工具配置、哪些 Gate、哪份政策以及哪个 commit 产生”，且能在注入已知错误时可靠阻断。
VERIFY THE SYSTEM

确定性正确

验证状态机、Artifact、哈希、Schema、事务、回滚、集合守恒和 Gate 组合逻辑。

VERIFY THE AGENT BOUNDARY

语义受控

验证 Agent 权限、输入冻结、输出协议、独立核验、弃权和相邻对象陷阱。

VERIFY THE DEFENSES

检查器有效

通过 defect corpus 和 mutation testing 证明 Gate 能抓住真实历史错误。

测试产物

  • 机器可读 Test Case Registry
  • 可重放 fixture 与 frozen artifact
  • JUnit/JSON Gate 报告
  • Mutation score 与逃逸缺陷账
  • Workflow replay 记录
  • Release verification manifest

03 / 12

范围、风险与优先级

测试优先级由“错误是否可能污染权威库、是否静默、影响范围是否跨行业”决定，而不是由实现复杂度决定。

等级定义典型风险准入要求
P0可能错误发布、丢数据或伪造证明越权写入、旧 Gate 复用、哈希漂移、错误 reviewed每次提交阻断；必须全自动
P1结果错误但可被后续 Gate 阻断错绑、漏 claim、预算失控、错误修复路由PR 阻断或 nightly
P2展示、可用性、性能或低影响退化章节顺序、Dashboard、非关键性能发布前完成

首批最高风险

状态与写入

  • 非法状态跳转
  • 并发重复 Apply
  • commit 中断未回滚
  • preview 污染 production

证据与语义

  • source verified 冒充 claim verified
  • ADJACENT 冒充 EXACT
  • excerpt 混入模型总结
  • 本地文件冒充外部证据

覆盖与报告

  • 应处理 claim 静默移出分母
  • 抽样结果外推全页/全行业
  • Gate PASS 超范围解释
  • 旧 Artifact 被新任务复用

运行与自治

  • 实际模型/工具权限漂移
  • 无限重试和成本失控
  • 自动修复从错误阶段开始
  • 高风险错误未进入异常队列
04 / 12

测试环境与测试数据

所有测试默认离线、无生产写权限；真实 Search/LLM 只允许在专门 canary 环境中运行，并冻结完整 attestation。

环境用途数据副作用
Unit Sandbox函数、Schema、属性测试内存对象 / tmp_path无
Integration SandboxSQLite、CAS、事务、CLI临时仓库 fixture仅临时目录
Replay LabWorkflow、失败恢复、缺陷复现冻结历史 Artifact无生产写入
Shadow真实 Agent 运行但不 Apply生产只读快照只写运行 Artifact
Canary小批 draft-only / 低风险发布白名单节点受控事务写入
Production Verify发布后校验和漂移检测正式 release只读，发现问题触发回滚

Fixture 家族

  • 最小合法 Graph：1 Activity + reference Product + background input
  • 含 D/E 冲突的 Graph candidate
  • Wiki Product / Activity Golden
  • 句号后脚注、多句共享脚注、未引用事实句
  • EXACT / ADJACENT / CONTRADICTED 来源包
  • 正常、中断、重复提交的 transaction journal
  • 跨行业唯一母行业 / 冲突 / no_node registry
  • BOM Exact / Coarse / Gap 混合样本
  • LCA Exact / Proxy / C0–C2 / rejection 样本
  • 运行模型、工具、argv、费用漂移 attestation

测试数据纪律

禁止测试直接读取完整行业大图；使用最小 fixture、精简索引或按节点提取。真实来源快照保存最小必要摘录和 hash，不保存敏感凭据。任何基于历史事故的 fixture 必须标注来源复盘、预期阻断层和影响版本。

架构—风险—测试追踪矩阵

每条架构决策必须对应至少一个正向测试、一个负向测试和一个故障恢复测试。

架构要求主要风险测试套件质量证据
Job 驱动隐式任务、无法重放CTL、WFJob schema + replay report
Agent 无直接写入越权污染权威库AGT、SEC、RELtool deny + no-write proof
不可变 Artifact结果被覆盖或错绑ART、WF、RELCAS hash + lineage
模块 Event 交互共享文件隐式耦合EVT、DOMevent contract + consumer idempotency
分层 GatePASS 超范围外推GATE、MUTscoped GateResult + mutation score
自动修复错误阶段重试、无限循环REP、WFrepair lineage + retry cap
原子发布部分写入、旧状态升级RELtransaction journal + post-verify
自治分级未达质量门自动发布SLO、E2Epromotion decision + audit sample

Mutation Score

Gate Mutation Score = 被 Gate 成功阻断的注入错误数 / 总注入错误数

P0 operators: 100% 必须被阻断
全部 operators: 初始 ≥95%
survived mutation: 必须登记缺陷、补 Gate 或明确接受理由

每个复盘发现的逃逸错误必须进入 tests/defects/，并标注受影响版本。修复当前页面不算完成；还要针对同脚本、同 Prompt、同政策版本生成追溯审计。

缺陷分类、恢复与回归

缺陷处理不是“让原 Agent 再想一次”，而是根据错误代码回到最早污染阶段并重建全部下游证明。

错误类别恢复策略必须回归的测试
Transient冻结输入下有限重试幂等、预算、retry cap
Protocol废弃错误输出，重跑当前 stepSchema、ID、hash、no-write
Evidence回到 nomination/search，不复用失败 evidencelocator、excerpt、alignment、coverage
Content回到 assemble，保留非退化基线内容合同、引用、Golden
Transactionjournal 驱动 rollback/resume部分提交、重复执行、stale hash
PolicyQuarantine + 人工 Decision影响分析、版本兼容、历史解释
Escaped defect发布标 defective、回滚、追溯同版本新增 fixture + mutation + 全仓扫描

缺陷完成定义

  • 当前错误已修复且回滚/恢复完成
  • 根因阶段被识别而非只修最终文本
  • 增加最小复现 fixture
  • 增加能失败后通过的回归测试
  • 新增或强化对应 Gate
  • 完成受影响版本追溯扫描
  • 更新 ADR/Policy（如需要）
  • 验证无质量或内容退化
