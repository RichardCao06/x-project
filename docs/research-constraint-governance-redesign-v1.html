Research Constraint Governance / v1

研究约束与 Agent 自治平衡设计

重新划分哪些规则必须阻塞、哪些规则应推动探索、哪些结论必须被证据证明， 让 Gate 回到“能否安全推进”的职责，让 Agent 在清晰的语义边界内自由选择检索与修复路径。

严格性应作用于证明，而不是搜索动作。 语义、来源、范围与不可逆发布必须严格；语言、关键词、来源组合与探索顺序必须自适应。

01 / Executive decision

不是减少 Gate，而是让每类规则待在正确的位置

当前设计的根本问题不是“规则太多”或“Agent 不够聪明”，而是缺少一等公民的约束类型、适用阶段和决策后果。 同一个布尔值同时承担安全校验、质量目标、搜索策略与完成判定，最终造成不该阻塞的地方过严、应该证明的地方过松。

目标架构应把“事实是否成立”与“如何找到事实”彻底分开：前者由契约和证据严格约束，后者由 Agent 在预算内自适应探索。

5 类约束类型，各自拥有不同的默认后果
3 条轴执行状态、Gate 决策、目标效果不再混为一谈
1 份账本每个研究问题都必须落到证据闭环状态
0 次盲重试没有策略差异证明，不允许消费下一次修复预算

保留刚性

身份一致性、事实蕴含、范围匹配、来源可追溯、哈希完整性、不可逆发布证明，以及被 completion goal 明确要求的关键字段。

释放自由

查询语言、关键词变体、Provider 顺序、来源组合、探索深度、段落长度和修复路径。它们应影响质量轨迹与下一步行动，而不是天然阻塞。

02 / Diagnosis

当前系统在两端同时失衡

过严与过松不是两个独立缺陷，而是同一建模缺口的两种表现：系统只知道“检查是否通过”，不知道这项检查究竟保护什么。

Over-constrained

在策略与启发式上过严

  • 语言覆盖英文查询字段曾被要求 100% 翻译，否则研究计划无法开工；但它本质是召回率策略。
  • 来源计数固定 URL、域名和语言数量被当成语义充分性的替代品。
  • 编辑形式固定句数、标题数、关键词保留和相似度阈值可直接阻塞，即使事实链已经成立。
  • 统一模板所有活动节点套用相同 claim slot 与表格下限，没有先判断字段是否适用。

Under-constrained

在语义与逻辑证明上过松

  • 问题定义identity_and_terminology 只是字符串标签，不包含稳定的实际问题、范围和排除项。
  • 计划到查询查询语言、问题和来源类别通过索引轮转分配，缺少显式语义关联。
  • 证据闭环存在 CONFIRMED 引用即可关闭事实，却未完整验证其是否蕴含结论、覆盖范围和对象身份。
  • 表格成熟度只填入一个字段也可能满足“有已采纳证据、有已填字段”，与生产完整目标不等价。
事件语义也在放大误解task.succeeded 代表命令执行成功，而 Dashboard 容易把它解释为业务阶段成功。
应拆成三条正交状态：execution_status 描述代码是否运行完成；gate_decision 描述是否允许推进； goal_effect 描述这次行动是否让最终目标发生了可证明的进展。三者任何一个都不能代替另外两个。
修复指纹过于粗糙相同错误消息被视为相同问题，但系统不知道问题契约、失败指标和搜索策略是否改变。
当前指纹主要依赖任务、错误码、类别、作用域和消息。它应增加 Gate 版本、失败 requirement IDs、指标区间、研究问题契约哈希和策略哈希， 同时把输入哈希与策略哈希分离，才能判断是“同因重试”还是“不同因果方案”。
03 / Case evidence

A019 不是“检索没有执行”，而是“执行完成但承诺没有兑现”

现有产物已经证明 A019 的执行链可以跑通，但研究计划的抽象标签没有被编译为稳定问题，查询也没有围绕缺口形成新的因果策略。 因此连续修复实际重复了近似动作。

研究计划 Gate：PASS_WITH_WARNING 的事实

英文翻译覆盖已经降为 advisory；这说明语言策略不应继续成为主卡点。

查看 research-plan-gate.json

检索执行 Gate：PASS

10 条查询完成，说明命令执行和查询调度本身不是阻塞原因。

查看 search-execution-gate.json

来源多样性 Gate：BLOCKED

最终只有 1 个确认 URL / 域名，且仅覆盖中文轨道；身份、流程与相邻活动区分等角色没有被证明。

查看 source-diversity-gate.json

修复动作：重复搜索，不是问题定向修复

回卷点保持在 research_ready，策略主要替换失败 URL/PDF；没有重写研究问题、查询意图或来源角色，所以无法产生可验证的边际进展。

正确结论

A019 当前应进入 EVIDENCE_LIMITED 或 RESEARCH_MORE，并明确指出未解决问题；不能把“查了 10 次”当成证据充分。

错误结论

不能仅因固定来源数量不够就认为语义失败，也不能因查询全部执行就认为研究完成。计数只能是风险信号，不能替代逐问题证明。

04 / Constraint model

五类约束，各自拥有不同的默认后果

每项检查必须声明类别、适用阶段、默认效果、升级为阻塞的条件，以及支持该判断的证据。任何未分类的布尔检查都不允许直接进入生产 Gate。

01 / invariant

不变量

保护真实性、完整性和不可逆操作。哈希不匹配、对象身份冲突、引用不存在、发布证明缺失时必须阻塞。

02 / applicability

适用性

先判断某项义务是否适用于当前节点。未判断适用性前，不允许把通用模板的全部字段强加给每个 Job。

03 / goal acceptance

目标验收

由 completion goal 和成熟度决定。reviewed publication 可以严格要求关键问题与关键字段，诊断运行则不应套用同一终态。

04 / quality target

质量目标

来源多样性、双语覆盖、编辑丰富度用于驱动补充研究、披露债务与质量评分；默认不直接证明事实失败。

05 / heuristic & budget

启发式与预算

查询数量、Provider 顺序、重试次数和候选上限只控制资源与策略；它们不得伪装成业务语义 Gate。

系统决定

问题骨架、对象范围、排除项、关键来源角色、验收条件、契约版本与哈希。

Agent 决定

查询措辞、语言、同义词、Provider、搜索顺序、是否追加探索问题和如何组合证据。

Agent 必须解释

新增问题为何相关、放弃某条路线的原因、每份证据支持到什么边界，以及哪些推论仍未成立。

06 / Stage responsibilities

从计划到发布，每一阶段只承担自己的证明义务

阶段边界应由输入契约、输出契约和推进条件定义，而不是由脚本退出码或文件存在性隐式定义。

阶段必须产出Gate 真正判断不应判断失败后的目标动作
研究计划 问题契约、适用性、来源角色、查询意图、关键程度 问题是否明确、可执行、可验收；关键语义是否完整 英文是否 100% 翻译、固定查询数量 补全问题骨架或适用性，不直接重复搜索
候选生成 query → question → source role 的显式映射 每个关键问题是否至少有可执行策略 用索引轮转语言、问题与来源类别 为未覆盖问题生成不同意图或不同 Provider
检索执行 关键词、Provider、结果、执行状态、耗时、错误 声明的策略是否真实执行，执行记录是否完整 把“查询完成”解释为“研究成功” 基础设施失败则重试；零结果则改变策略
证据核验 采纳/拒绝理由、支持类型、范围、冲突与缺口 证据是否真实支持对应问题与结论边界 仅依赖 URL/域名计数证明充分性 精确定位未闭环问题，生成差异化修复输入
组合质量 来源组合、语言组合、独立性、代表性债务 组合风险与最终目标要求是否相容 默认用固定数量阻塞所有运行 补充来源或形成可见的 evidence-limited 结论
正文与表格 claim-evidence ledger、字段关键级、适用性和缺口 事实、范围、引用和关键字段是否足以支撑目标 以句数、标题数或“填了一个字段”替代语义完整 修正文/字段或降低成熟度，不伪造完成
正式发布 审查决策、不可变 release、产物与哈希绑定 所有目标验收约束与发布不变量是否满足 把 preview 可访问等同于生产成功 明确阻塞或回卷到精确缺口阶段
来源多样性需要拆成两个组件“问题是否被证明”与“证据组合是否理想”不应由同一个计数 Gate 代替。
  • question_evidence_sufficiency_gate：逐个关键问题检查直接支持、范围和来源角色，属于目标验收约束。
  • portfolio_quality_assessment：评估独立来源、语言、地域与来源类型的组合风险，通常给出质量债务与扩展建议。
  • 只有 completion goal 明确要求交叉验证，或单一来源无法支撑高风险结论时，组合质量才升级为阻塞。
表格字段需要关键级，而不是统一必填将字段划分为 required_for_model、recommended 与 contextual。
对每个字段先记录 applicable / not_applicable / unresolved，再根据 completion goal 计算成熟度。 “已填字段 > 0”只能表示出现进展，不能表示 model ready，更不能表示 reviewed publication ready。
07 / Decision semantics

Gate 不再只返回 PASS / BLOCKED

决策必须说明：能否推进、携带什么债务、缺少什么证明、下一步由谁负责。这样既不会把质量建议误当硬失败，也不会把执行成功误当目标完成。

PASS

所有当前阶段的刚性约束与目标验收条件满足，可以进入下一阶段。

PASS_WITH_DEBT

可以推进，但质量债务必须进入 Dashboard、后续提示词和最终发布决策，不能被丢失。

RESEARCH_MORE

关键问题尚未闭环，但存在可行动的新策略。修复系统必须先生成策略差异证明，再消费预算。

EVIDENCE_LIMITED

已合理探索但公开证据不足。允许以显式缺口结束研究阶段；能否发布由 completion goal 和风险等级决定。

BLOCKED_INTEGRITY

事实冲突、身份/范围不一致、引用不可解析、哈希或不可逆发布证明失败。必须阻塞，不允许通过降级绕过。

NOT_APPLICABLE

该义务不适用于本节点，且有明确适用性判断依据。它不是跳过失败，而是可审计的契约结果。

08 / Autonomous repair loop

自修复必须改变因果输入，而不是只改变随机样本

没有失败证据包、没有策略差异、没有预期证明的修复，不是一次有效修复，只是重跑。

01 / OBSERVE

完整失败包

Gate JSON、失败 requirement IDs、指标、问题状态、输入/策略哈希和关联产物必须一起进入 Triage。

02 / EXPLAIN

因果分类

区分问题契约缺失、查询策略失配、抓取失败、解析零产出、证据稀缺、事实冲突和发布基础设施故障。

03 / CHANGE

策略差异证明

列出本轮改变了哪些问题、查询意图、Provider、解析器或代码路径，以及为何可能改变结果。

04 / VERIFY

边际进展

比较逐问题闭环率、证据支持强度与关键字段成熟度。两轮零增益后必须换因果方案或诚实终止。

修复预算属于“不同因果方案”，不属于“相同命令的重复次数”。
失败类型修复目标必须产生的变化禁止动作
身份证据缺失问题契约 / 查询意图更具体的对象、活动边界、排除项和权威来源角色仅替换一个 URL 后重跑
查询零结果词汇与 Provider同义词、语言、制造商站点、文档类型或相邻概念路径改变完全相同的 query/provider 组合
抓取失败候选与网络路径镜像、HTML 替代、存档或候选替换回卷整个研究计划
解析零产出抽取器内容类型识别、OCR/表格抽取或解析适配把解析问题误判成来源不足
公开证据稀缺状态与披露形成 evidence-limited、明确缺口与后续人工材料请求无限搜索或伪造闭环
事实/范围冲突证据与结论降低结论范围、标记冲突或补充独立证据以来源数量覆盖冲突
故障指纹 v2指纹必须能区分“相同症状，不同因果方案”。
建议包含：gate_id/version、failed_requirement_ids、关键指标分桶、 question_contract_hash、strategy_hash、代码基线与输入产物哈希。 其中策略哈希单独参与“是否允许再修复”的判定，不能被输入文件变化掩盖。
Logic Audit 保持只读审查它负责发现推理断点和提出疑问，不直接控制流水线推进。
Logic Audit 可以标记“结论缺少前置条件”“问题拆解在不同 Session 不一致”“引用只提供背景而非直接支持”。 若某类观察需要升级为 Gate，必须先经过约束治理：定义类别、适用范围、误报成本、验收数据和版本迁移，不能由审查器临时阻塞 Job。
09 / Completion ladder

用成熟度阶梯替代含混的“预览成功”

Preview 是呈现方式，不是业务完成状态。系统可以生成预览，但 Job 的 completion goal 只有在对应成熟度和发布证明满足时才完成。

L0

diagnostic_complete

执行链可观察，故障有证据包。

L1

research_executed

计划中的策略真实执行，但证据未必充分。

L2

evidence_limited

合理探索完成，关键缺口被诚实披露。

L3

model_ready

关键问题与 required_for_model 字段闭环。

L4

reviewed_ready

审查债务可接受，正式发布条件满足。

L5

published

不可变 release 与产物哈希证明有效。

Preview 的新语义

任何成熟度都可生成只读预览，用于观察、审查和修复；预览 URL 的存在不会改变 Job status，也不会让 Supervisor 退出。

Reviewed publication 的新语义

只有 L5 才满足 completion_goal=reviewed_publication：publish 成功、审查有效、release record 不可变且与最终产物哈希绑定。

10 / Implementation sequence

先修可观察性和语义，再迁移 Gate

如果直接放宽现有 Gate，会得到更快但更不可控的流水线。实施顺序必须先保证失败可解释、问题可复现、修复可比较。

事件与失败包

拆分 execution / decision / goal effect；确保 blocked Gate 也附带原始 Gate JSON、失败要求和关联产物。修正仅在 status=failed 才附加 JSON 的分支。

研究问题契约 v2

新增版本化 ontology、确定性问题编译器和契约哈希；保留 Agent 扩展问题，但扩展必须有理由和 provenance。

显式语义映射

替换按 index/modulo 轮转的问题、语言与来源类别分配，建立 question → query intent → query → source role 全链路 ID。

证据账本与 Gate 拆分

新增逐问题证据闭环状态；将来源多样性拆成证据充分性 Gate 与组合质量评估。

内容与表格成熟度

引入字段适用性和关键级；正文检查从固定句数迁移到 claim-evidence entailment、范围与关键问题覆盖。

差异化自修复

升级故障指纹、策略哈希与边际进展；没有策略差异证明禁止重复，证据稀缺允许形成明确终态。

11 / Acceptance criteria

何时算这次设计真正落地

验收不以“测试通过”或“页面有新字段”为终点，而以系统是否能稳定做出不同、可解释、可复现的决策为终点。

跨 Session 稳定

同一节点与 ontology 版本生成相同核心问题、范围和排除项；Agent 扩展问题有显式 provenance。

策略自由可审计

Agent 可选择语言、关键词和 Provider，但每条查询都能回溯到 question_id 与 query_intent_id。

Gate 不误权

启发式默认不能直接阻塞；不变量失败不能通过降级、预览或人工描述绕过。

证据逐问题闭环

每个关键问题都有 confirmed、partial、contradicted、explicit_gap 或 not_applicable 状态及证据。

零盲重试

第二次修复前必须存在非空策略差异；两轮零边际增益后必须换因果方案或停止。

完成度不再含混

Preview 可查看但不改变 completion goal；reviewed publication 只有不可变 release 证明后完成。

失败信息完整

Dashboard 可查看 Gate 原文、失败要求、指标、查询、来源、采纳/拒绝理由和修复变化。

A019 回归样例

系统能区分“10 次查询已执行”与“身份问题未证明”，并给出定向补研或 evidence-limited，而非重复相同搜索。

最终标准不是让 Agent 更自由，也不是让规则更严格，而是让自由发生在策略空间，让严格发生在证明边界。

用契约固定含义，用 Agent 探索路径。
